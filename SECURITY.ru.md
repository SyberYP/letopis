# Безопасность «Летописи»

[English](SECURITY.md) · **Русский**

## Что защищено и от кого

| Угроза | Защита |
|---|---|
| Кто-то получил файлы приложения (резервная копия, root, украденный телефон без пароля) | Всё зашифровано AES-256-GCM. Ключ данных (DEK) завёрнут ключом из пароля (Argon2id, 19 МиБ, 2 прохода). Без пароля файлы бесполезны |
| Подмена или перестановка зашифрованных файлов | Путь файла (`entries/<id>`, `media/<id>`…) входит в AAD каждого блока: файл, переложенный под другое имя, не расшифруется |
| Чужой или испорченный репозиторий синхронизации | Берутся только пути вида `vault.json`, `entries/<id>.md.enc`, `media|thumbs/<id>.enc`. `vault.json` из репозитория принимается, только если открывается текущим ключом |
| Импорт файла с «ловушками» в id или имени вложения (`../`) | id проверяется (`[A-Za-z0-9_-]{1,64}`), расширения — `[a-z0-9]{1,10}`, у импортированных записей новый id и нет чужих вложений |
| `vault.json` с огромными параметрами Argon2id (зависание, нехватка памяти) | Параметры ограничены: память ≤ 2 ГиБ, проходов ≤ 64, потоков ≤ 16 |
| Утечка открытого текста в публичный репозиторий | Режим «открытый Markdown» проверяет, что репозиторий приватный, иначе не отправляет ничего |
| Утечка текста записи по сети | Сеть — только GitHub (токен пользователя) и выбранный ИИ-сервис (только HTTPS, после согласия; согласие сбрасывается при смене адреса). Ссылки из записей открываются после подтверждения |
| Поддельное обновление | Все сборки подписаны ключом загрузки (вне репозитория). Старый личный ключ с публичным паролем выведен ротацией подписи (v3) без права отката: подписанный им APK не встанет поверх версии 1.1.1+ |
| Подглядывание | Автоблокировка при сворачивании, запрет скриншотов (`FLAG_SECURE`, по желанию) |

Открытый текст на диске бывает только во временной папке воспроизведения видео/аудио и при
«Поделиться» (временный файл) — папка чистится при блокировке.

## Известные ограничения

- **Биометрия.** При включённой разблокировке отпечатком ключ данных хранится в
  `flutter_secure_storage` (шифруется ключом Android Keystore), а запрос отпечатка делает приложение.
  Ключ Keystore не привязан к подтверждению биометрией: при полном доступе к процессу (root,
  отладчик) ключ можно получить без отпечатка. Без биометрии этого риска нет. Исправление —
  `AndroidOptions.biometric(enforceBiometrics: true, requireBiometricsPerOperation: true)`; требует
  проверки на устройстве.
- **Метаданные.** Количество, размер и время изменения файлов видны тому, у кого есть доступ к
  файлам или к репозиторию синхронизации. Теги и текст — нет.
- **Забытый пароль** восстановить нельзя (так задумано).
- **Токен GitHub** хранится в зашифрованных настройках; выдавайте fine-grained токен на один
  репозиторий с правом *Contents: Read and write*.
