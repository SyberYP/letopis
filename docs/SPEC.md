# Техническое задание: «Летопись» — личный дневник

*Версия 0.3 от 26.10.2026 (0.1 — первая; 0.2 — уточнено по ходу реализации MVP; 0.3 — плитки, корзина, настроение, статистика, подготовка к сторам). Автор идеи — Александр Былинский. Всё, что помечено **[решить]**, ждёт ответа автора.*

---

## 1. Коротко

Мобильное приложение для ведения дневника. Каждая запись — Markdown-документ со временем создания,
хэштегами и вложениями (фото, аудио, видео). Все данные на устройстве хранятся только в
зашифрованном виде. Записи можно синхронизировать с git-репозиторием (GitHub), а хэштеги — расставлять
вручную или с помощью нейросети через API (OpenRouter или любой OpenAI-совместимый сервис).

Сначала — личное приложение автора на Android. Архитектура сразу готова к iOS и к публикации в
сторах: нет зашитых ключей и личных данных, есть русский и английский интерфейс, политика
конфиденциальности описывается одной фразой: «данные не покидают устройство, пока вы сами не
подключили git или ИИ».

### 1.1. Принципы
1. **Записать мысль — за 2 касания.** Открыл приложение → «+» → пишешь. Время ставится само.
2. **Приватность по умолчанию.** Ничего не уходит в сеть без явного действия пользователя.
   Шифрование нельзя выключить.
3. **Данные принадлежат пользователю.** Формат — обычный Markdown с YAML-шапкой. Экспорт в один
   ZIP. Git-зеркало можно читать без приложения (в открытом режиме).
4. **Красиво и спокойно.** Material 3, крупная читаемая типографика, тёмная тема, без рекламы.

## 3. Функциональные требования

### 3.1. Записи
- Поля: `id` (UUID v4), `created` (дата и время с часовым поясом, ставится при создании, можно
  изменить), `updated`, `title` (необязательный), `body` (Markdown), `tags` (список),
  `attachments` (список), `mood` (необязательно, 1–5 — **[решить]** нужно ли), `location` — не в MVP.
- Формат файла записи — Markdown с YAML-шапкой (front matter):

  ```markdown
  ---
  id: 6f1c…
  created: 2026-10-25T09:41:00+03:00
  updated: 2026-10-25T09:55:12+03:00
  title: Утро
  tags: [семья, дочь]
  attachments:
    - {id: a1b2…, type: photo, name: IMG_2041.jpg, mime: image/jpeg}
  ---
  Текст записи в **Markdown**. #мысль
  ```
- Хэштеги: объединение тегов из шапки и `#слов` в тексте (буквы, цифры, `_`, `-`; кириллица
  поддерживается). Теги хранятся в нижнем регистре без `#`.
- Редактор: панель Markdown (жирный, курсив, заголовок, список, чек-лист, цитата, ссылка,
  разделитель), переключатель «Текст / Просмотр», счётчик слов, автосохранение (через 1,5 с после
  последнего изменения и при выходе).
- Удаление — с подтверждением и кнопкой «Отменить»; удалённые записи 30 дней лежат в «Корзине»
  (`trash/`, зашифрована, не синхронизируется), потом стираются. Из корзины — вернуть или удалить навсегда.
- Лента — двумя режимами: карточки (список) и плитки (сетка 2 колонки: фото на всю плитку или текст
  с датой и первым тегом). Выбор запоминается.
- Настроение 1–5 (необязательно, выбор в редакторе), среднее — в статистике.
- Статистика: записи, слова, дни, серия дней сейчас и самая длинная, по месяцам за год, по дням
  недели, топ тегов.

### 3.2. Вложения
- Фото: галерея (несколько сразу) и камера. Видео: галерея и камера. Аудио: запись в приложении
  (AAC/m4a) и выбор файла. Любой файл — «Файл».
- Каждое вложение шифруется отдельным файлом. Миниатюры фото (≤ 480 px) — тоже зашифрованы.
- Просмотр: фото — полноэкранная галерея с зумом; видео — плеер; аудио — плеер с прогрессом
  прямо в записи. Для воспроизведения файл расшифровывается во временную папку приложения и
  удаляется при блокировке.
- Вложения показываются под текстом (галерея, плееры). В текст их можно вставить ссылкой
  `![](att:<id>)` (фото) или `[🎙 Голос](att:<id>)`: просмотр покажет фото прямо в тексте, а в
  git-зеркале и экспорте ссылки переписываются в относительные пути. Кнопки «вставить в текст» в MVP
  нет (TODO).

### 3.3. Лента и просмотр
- Лента: группировка по месяцам, «липкие» заголовки месяцев, карточка с датой (день крупно),
  временем, заголовком или первой строкой, двумя-тремя строками текста, миниатюрой первого фото,
  значками аудио/видео и тегами.
- «В этот день» — горизонтальная карусель над лентой, если есть записи того же дня/месяца прошлых лет.
- Календарь месяца с точками в днях с записями; тап по дню — записи дня.
- Теги: экран всех тегов с количеством; тап — лента по тегу.
- Поиск: подстрока без учёта регистра по заголовку, тексту и тегам, совпадения подсвечиваются.
- Статистика: число записей, дней подряд (серия), слов всего — в шапке ленты/настройках.

### 3.4. Безопасность (обязательно)
- **Модель угроз:** потерянный/украденный телефон; копия папки приложения (бэкап, root); утечка
  git-репозитория; перехват трафика. Вне модели: заражённое устройство с кейлоггером.
- Пароль задаётся при первом запуске (≥ 6 символов, рекомендуется фраза). Из пароля
  выводится ключ **KEK = Argon2id(пароль, соль 16 байт; m = 19 МиБ, t = 2, p = 1)** (параметры
  OWASP 2024+, хранятся в файле, их можно усилить).
- Данные шифрует случайный **DEK** 256 бит. DEK хранится только «завёрнутым»: `AES-256-GCM(KEK, DEK)`
  в `vault.json` (соль, параметры, nonce, шифртекст). Смена пароля перешифровывает только DEK.
- Каждый файл (запись, вложение, миниатюра, индекс) — **AES-256-GCM** с новым случайным nonce
  96 бит; формат: `LTP1` (4 байта) | nonce (12) | шифртекст | tag (16). Имя файла — UUID, без
  дат и заголовков.
- Разблокировка по биометрии: DEK кладётся в Android Keystore / iOS Keychain
  (`flutter_secure_storage`), доступ — только после `local_auth`. Выключается в настройках.
- Автоблокировка: при сворачивании дольше N секунд (по умолчанию 60; варианты 0/60/300) DEK
  стирается из памяти, временные расшифрованные файлы удаляются.
- Ключи API (OpenRouter, GitHub) хранятся в зашифрованных настройках (тем же DEK).
- Запрет скриншотов и превью в списке приложений (`FLAG_SECURE`) — по умолчанию включён.
- Пароль восстановить нельзя — это говорится при создании. Подсказка к паролю — **нет** (утечка).
- Всё общение с сетью — только HTTPS.

### 3.5. Синхронизация с git
- Провайдер MVP — **GitHub** через REST API (Git Data API: blobs → tree → commit → ref), токен
  fine-grained с правом *Contents: read and write* на один репозиторий. Это работает с телефона без
  нативного git. Gitea/GitLab/Bitbucket и «настоящий» git по HTTPS — в TODO (интерфейс
  `RemoteRepo` уже абстрагирован).
- Настройки: владелец/репозиторий, ветка (по умолчанию `main`), папка внутри репозитория
  (по умолчанию `letopis/`), режим.
- **Режим «Зашифрованный»** (по умолчанию). В репозиторий уходят те же зашифрованные файлы и
  `vault.json`. Двусторонняя синхронизация: для каждой записи сравниваются `updated` (побеждает
  более поздняя; при конфликте ничего не теряется — проигравшая версия сохраняется копией
  «(конфликт)»). Вложения неизменяемы — синхронизируются по наличию. Удаления — через список
  `tombstones` в зашифрованном манифесте.
- **Режим «Открытый Markdown»**. Только отправка (зеркало): `entries/ГГГГ/ММ/ГГГГ-ММ-ДД-ЧЧММ-заголовок.md`
  + `media/<id>.<ext>`, ссылки `att:` переписываются в относительные пути. Читается на GitHub и
  любым редактором (например, Obsidian). Предупреждение: репозиторий должен быть приватным.
- Синхронизация — по кнопке и (по желанию) после каждого сохранения с задержкой 30 с; фоновая — TODO.
- Восстановление на новом устройстве: «Восстановить из git» → токен, репозиторий → пароль →
  расшифровка `vault.json`.
- Коммит одной операцией на синхронизацию, сообщение: `Летопись: 3 записи, 2 вложения (Pixel 8)`.

### 3.6. ИИ-хэштеги
- Провайдер — любой OpenAI-совместимый `chat/completions`; по умолчанию OpenRouter
  (`https://openrouter.ai/api/v1`), модель задаётся строкой (по умолчанию дешёвая быстрая модель
  **[решить]**; поле редактируемое), ключ пользователя.
- Запрос: системная инструкция + до 6000 символов записи + список уже существующих тегов (до 200),
  чтобы ИИ переиспользовал словарь, а не плодил синонимы. Ответ — JSON `{"tags": [...]}` (3–7 тегов,
  язык записи, нижний регистр). Устойчивый разбор: JSON → массив в тексте → строки через запятую.
- UX: кнопка «✨ Подобрать теги» в редакторе → чипы-предложения → тап добавляет. Опция
  «Подбирать автоматически при сохранении» (по умолчанию выключена).
- Предупреждение при первом использовании: текст записи уходит стороннему сервису.
- Вложения в ИИ не отправляются.

### 3.7. Импорт и экспорт
- Импорт текстовой выгрузки дневника автора (два формата, см. С8) — с предпросмотром числа записей
  и диапазона дат; дубликаты (та же дата-время и текст) пропускаются.
- Импорт `.md` файлов (с шапкой или без; дата — из шапки или имени файла).
- Экспорт: ZIP с открытым Markdown + media (как git-зеркало) через «Поделиться». Предупреждение,
  что архив не зашифрован.

### 3.8. Настройки
Тема (система/светлая/тёмная), акцентный цвет, язык (рус/англ), автоблокировка, биометрия,
запрет скриншотов, смена пароля, ИИ (URL, ключ, модель, авто), git (репозиторий, токен, режим,
автосинхронизация), импорт, экспорт, «О приложении».

## 5. Архитектура

| Слой | Что | Где |
|---|---|---|
| Крипто | Argon2id, AES-GCM, формат `LTP1`, vault | `lib/core/crypto.dart`, `lib/core/vault.dart` |
| Модель | `Entry`, `Attachment`, front matter, хэштеги | `lib/core/entry.dart`, `lib/core/markdown_io.dart` |
| Хранилище | Зашифрованные файлы на диске, индекс в памяти | `lib/core/store.dart` |
| Сервисы | ИИ-теги, git-синхронизация, импорт/экспорт | `lib/services/` |
| Состояние | `AppState` (ChangeNotifier): блокировка, записи, настройки | `lib/state/` |
| UI | экраны и виджеты | `lib/ui/` |

Раскладка данных на устройстве (`<documents>/letopis/`):
```
vault.json                 соль, параметры Argon2id, завёрнутый DEK (не секрет без пароля)
settings.enc               настройки и ключи API
index.enc                  кэш всех записей для быстрого открытия (не синхронизируется)
entries/<uuid>.md.enc      записи
media/<uuid>.enc           вложения
thumbs/<uuid>.enc          миниатюры
sync.enc                   состояние синхронизации (SHA файлов на сервере, tombstones)
```

Стек: Flutter (Dart 3), `cryptography` (+ `cryptography_flutter` для нативного AES), `flutter_secure_storage`,
`local_auth`, `image_picker`, `file_picker`, `record`, `just_audio`, `video_player`,
`flutter_markdown_plus`, `http`, `archive`, `share_plus`, `provider`.

Сборка только локально (GitHub Actions не используется): `flutter test`, `flutter build apk --release`
(личный ключ, выкладывается на letopis.recalltwin.com), `flutter build appbundle --release` (ключ
загрузки для сторов из `android/key.properties`, вне git).

## 6. Не входит в MVP
Веб-версия и ПК; совместное ведение; напоминания; геолокация и погода; распознавание речи
(диктовка — системной клавиатурой); сквозной поиск по аудио; облако кроме git; встроенные
покупки.

загрузки, AAB, скриншоты, тексты карточки и ответы анкет — `docs/store/`. Разрешение камеры убрано
(съёмку делает системная камера). Сама публикация — только по явному «да» автора и через `решение`
в рабочем пространстве.
