## Установка и обновление

1. Последняя сборка: <https://letopis.recalltwin.com> — открыть на телефоне и скачать `letopis.apk`.
2. Собрать самому: `flutter build apk --release --flavor site`, выложить: `deploy/deploy.sh` (APK, страница
   скачивания и политика конфиденциальности). Сборка только локальная, GitHub Actions не используется.
3. Новая версия ставится поверх старой, записи сохраняются (см. «Подпись»). Версия с сайта — Android 9+.
   В ней есть кнопка «Настройки → Проверить обновления»: по нажатию спрашивает
   `letopis.recalltwin.com/version.json` и предлагает открыть сайт. Само приложение в сеть не ходит;
   в сборках для сторов кнопки нет (обновляет магазин).

### Варианты сборки (flavors)
| Flavor | Куда | Что отличается | Команда |
|---|---|---|---|
| `site` | letopis.recalltwin.com | «Проверить обновления», «Поддержать» → CloudTips; компоненты RuStore SDK вырезаны из манифеста | `deploy/deploy.sh` |
| `rustore` | RuStore | «Поддержать» → RuStore Pay | `flutter build apk --release --flavor rustore` |
| `play` | Google Play (после 15.01.2027) | без обновлений и поддержки; SDK вырезан | `flutter build appbundle --release --flavor play` |

Dart узнаёт вариант через `appFlavor` (`lib/services/channel.dart`).

Данные на устройстве (`<app support>/letopis/`):

```
vault.json             соль и параметры Argon2id, завёрнутый ключ данных (без пароля бесполезен)
settings.enc           настройки, ключи API и токен GitHub
index.enc              кэш всех записей для быстрого открытия (не синхронизируется)
trash.enc, trash/      корзина: удалённые записи и их вложения, 30 дней (не синхронизируется)
entries/<uuid>.md.enc  записи
media/<uuid>.enc       вложения
thumbs/<uuid>.enc      миниатюры фото
```

### Синхронизация
- **Зашифрованный режим** (по умолчанию): в папку репозитория уходят те же `.enc`-файлы и `vault.json`.
  Сравнение трёхстороннее по SHA git-блобов (локально, удалённо, на момент прошлой синхронизации).
  Правки в обе стороны; если запись менялась на двух устройствах — побеждает более поздняя, вторая
  версия сохраняется отдельной записью с тегом `#конфликт`. Правка сильнее удаления.
  Новый телефон: «Восстановить из облака или GitHub» на первом экране + пароль.
- **Открытый Markdown** (только отправка): `entries/ГГГГ/ММ/ГГГГ-ММ-ДД-ЧЧММ-заголовок.md` + `media/`.
  Только для приватного репозитория.
- Токен: fine-grained, один репозиторий, *Contents: Read and write*.
- Ограничение GitHub API: файл не больше 95 МБ (длинные видео не уйдут в git).

### Облако (WebDAV)
- Тот же движок (`SyncEngine`), другое хранилище (`WebDavRepo`). Одновременно работает одна цель:
  облако или GitHub (`AppState.syncTarget`); подключение одной отключает другую.
- В WebDAV нет коммитов, поэтому в папке лежат опись `letopis-sync.json`
  (`{"format":1,"rev":"<uuid>","files":{"путь":"sha"}}`) и сами файлы в `objects/<sha git-блоба>`.
  Файл никогда не перезаписывается другим содержимым — два телефона не затрут загрузку друг друга.
  Опись пишется последней и только если `rev` не изменился с начала синхронизации; иначе — конфликт,
  движок начинает заново (до 3 попыток). Скачанный файл сверяется с sha. После записи описи удаляются
  объекты, на которые она больше не ссылается. `README.md` кладётся в папку обычным файлом.
- Только HTTPS; HTTP — для адресов домашней сети (10/8, 172.16/12, 192.168/16, localhost, `.local`, `.lan`).
  Авторизация Basic (логин + пароль приложения).
- Пресеты: Яндекс Диск `https://webdav.yandex.ru` (по справке Яндекса — тарифы Яндекс 360, пароль приложения
  «Файлы WebDAV»), Облако Mail.ru `https://webdav.cloud.mail.ru` (может требовать платный тариф),
  Nextcloud/ownCloud `https://сервер/remote.php/dav/files/ЛОГИН`.
- Проверено 26.10.2026 на эмуляторе с локальным сервером wsgidav: синхронизация и восстановление на чистой
  установке. На настоящих Яндекс Диске и Nextcloud — ещё нет.

### Экспорт в PDF
Настройки → Экспорт в PDF (весь дневник или год, фото вкл/выкл) и «Поделиться → PDF» у записи. Книга A5:
обложка, записи от старых к новым, заголовки месяцев, Markdown (заголовки, выделение, списки и списки дел,
цитаты, код, таблицы), фото (уменьшены до 1100 px), список прочих вложений, теги, номера страниц.
Подготовка (расшифровка, уменьшение фото) — в основном потоке с прогрессом, вёрстка — в отдельном isolate.
Шрифт книги — тот, что выбран в настройках (PT Serif для «классического» и «системного»), плюс Noto Emoji
(SIL OFL 1.1, лицензии рядом в `assets/fonts/`); в PDF попадают только использованные символы. Файл не
зашифрован, пишется во временную папку (чистится при блокировке).

Другие письменности. На Android для арабского, деванагари, бенгальского, греческого и вьетнамских знаков
читаются системные шрифты из `/system/fonts` (`systemFallbackFonts`, только если такие буквы есть в тексте,
только локально). Абзац с первой «сильной» буквой арабского письма идёт справа налево и выравнивается вправо
(`textDirectionOf`). Библиотека `pdf` отдаёт шрифту-заменителю каждую недостающую букву отдельно, и
арабские буквы не соединяются, поэтому арабские слова заранее собираются в отрезки (`arabicRun`) с арабским
шрифтом как основным. Ограничения библиотеки (pdf 3.13): нет TrueType-шрифта для китайского и японского в
современном Android (только `.ttc`/CFF) — иероглифы в PDF квадратиками; хинди и бенгальский без лигатур;
арабское слово внутри абзаца слева направо и хинди внутри абзаца справа налево выходят перевёрнутыми.
Подписи книги (даты, «Настроение») — на языке интерфейса для ru, en, es, fr, pt, de, id, vi, для остальных —
по-английски.

### Языки и шрифты
15 языков (`languages` в `strings.dart`): ru, en, zh, hi, es, ar, fr, bn, pt, id, ur, de, ja, mr, vi — топ по
числу говорящих (Ethnologue 2026 через Википедию), без нигерийского пиджина и египетского арабского (пишут
по-английски и на литературном арабском). Ключ без перевода берётся из en, затем ru. Множественное число —
по CLDR: суффиксы `_1` (one), `_2` (few), `_5` (many/other), у арабского ещё `_0`, `_two`, `_other`
(`pluralCategory`). Тест «every UI string exists in every language» проверяет ключи и `{плейсхолдеры}`.
Переводы сделаны ИИ и носителями не вычитаны. Арабский и урду — справа налево: в вёрстке
`EdgeInsetsDirectional`, `AlignmentDirectional`, `PositionedDirectional`.

Шрифты (`AppFont`): классический (системный + PT Serif в заголовках), системный, PT Serif, Lora, Comfortaa,
Caveat, PT Mono — все SIL OFL, статические начертания (Lora, Comfortaa, Caveat сделаны из вариативных через
`fontTools.varLib.instancer`). У рукописного и округлого свой масштаб (`FontChoice.scale`). Букв, которых нет в
шрифте (арабский, хинди, китайский), Flutter берёт из системного.

```bash
flutter pub get
flutter analyze
```

`../источники/дневник/allentries.txt`; в отдельном репозитории он пропускается.

### Подпись
Все release-сборки (`flutter build apk|appbundle --release --flavor …`) подписываются
**ключом загрузки** (`upload`) из `android/key.properties`; сам файл ключа лежит вне репозитория. Без
`key.properties` release-сборка падает. Debug-сборки — стандартным debug-ключом Android.

| Куда | Что | Команда |
|---|---|---|
| RuStore | APK flavor `rustore`; для AAB консоль требует загрузить закрытый ключ, поэтому используем APK | `flutter build apk --release --flavor rustore` |
| Google Play | AAB flavor `play` (Google переподписывает своим ключом, Play App Signing) | `flutter build appbundle --release --flavor play` |
| Сайт | APK flavor `site` + доказательство ротации ключа, подпись v3 (Android 9+) | `deploy/deploy.sh` (сам собирает, вызывает `deploy/sign-site.sh`, пишет `version.json`) |

**Ротация.** До 1.1.1 личные сборки подписывались ключом `letopis-dev.jks` с публичным паролем
`android` (он остался в истории git). С 1.1.1 ключ выведен: `deploy/signing-lineage.bin` — подписанное
старым ключом разрешение перейти на ключ загрузки (APK Signature Scheme v3). Телефон со старой версией
принимает новую как обычное обновление, данные сохраняются; после этого старый ключ обновить
приложение не может (у него нет права отката). Проверено на эмуляторе Android 14, 26.10.2026.
Сайт и RuStore подписаны одним ключом и ставятся друг поверх друга; версия из Google Play — нет (другой ключ).

Формат `key.properties`:

```
storeFile=C:/Users/<имя>/.letopis/letopis-upload.jks
storePassword=…
keyAlias=upload
keyPassword=…
```

Ключ загрузки и пароль хранить в менеджере паролей и в резервной копии: без них не выпустить
обновление в RuStore (в Google Play ключ загрузки можно сбросить через поддержку, ключ подписи
приложения хранит Google). Перед переходом на версию из Google Play — синхронизировать с GitHub
или сделать экспорт: её ключ другой, поверх не встанет.

## Поддержка автора: как устроено
Всё в приложении бесплатно, платных функций нет. «Настройки → Поддержать проект»:
- версия с сайта — страница CloudTips (разовый платёж любой суммы картой);
- версия из RuStore — разовые покупки `support_99`, `support_299`, `support_999` через RuStore Pay
  (`lib/services/support.dart`). Покупка ничего не открывает. Нужны: ИП с подключённой монетизацией в
  RuStore Консоли, эти три товара (тип «потребляемый»), id приложения из консоли в
  `android/gradle.properties` → `letopisRustoreAppId`. Заявление с УКЭП принято 04.11.2026, три товара
  опубликованы (99, 299 и 999 ₽). Тестовую покупку ещё нужно провести на Android-устройстве с RuStore;
- версия для Google Play — кнопки нет (правила Play; выплаты на российские счета закрыты).
