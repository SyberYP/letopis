# Работа над «Летописью»

Инструкции для ИИ-ассистентов (Claude Code, Cursor и др.). Автор пишет по-русски — отвечать по-русски.
Код, идентификаторы и сообщения коммитов кода — на английском (коммиты в рабочем пространстве `life` — на
русском, по его правилам).

Прочитать сначала: `README.md` (устройство), `docs/SPEC.md` (ТЗ), `docs/TODO.md` (что открыто).

## Правила, которые легко нарушить
- **Шифрование не ослаблять.** Ничего из записей, вложений, ключей API и токенов не пишется на диск в
  открытом виде, кроме временной папки воспроизведения (`AppState.temp`, чистится при блокировке).
  Формат `LTP1` и `vault.json` менять только с миграцией и тестом на чтение старых файлов.
- **Контекст шифрования = путь** (`entries/<id>`, `media/<id>`, `thumbs/<id>`, `settings`, `sync`,
  `index`). Новый тип файла — новый контекст.
- **Формат записи — Markdown + YAML-шапка** (`markdown_io.dart`). Он же уходит в git и экспорт:
  поля только добавлять, старые файлы должны читаться.
- **Синхронизация трёхсторонняя** (`sync.dart`): любое изменение логики — с тестом на двух
  устройствах в `test/services/sync_test.dart`.
- **Тексты интерфейса** — ключи в `lib/l10n/strings.dart`, в обоих языках (тест это проверяет).
- **Ничего не отправлять в сеть** без явного действия пользователя (git, ИИ). ИИ получает только текст
  записи, без вложений, после согласия.
- **Секреты не в git**: `android/key.properties`, ключ магазина. Исключение — `letopis-dev.jks` для
  личных сборок (см. README, «Подпись»).
- **Публикация в сторах** — только по явному «да» автора.

## Тесты
`flutter analyze && flutter test` перед каждым коммитом. Скриншоты экранов:
`SCREENSHOTS=1 flutter test test/ui/screenshots_test.dart --update-goldens` — посмотреть глазами после
изменений интерфейса.
